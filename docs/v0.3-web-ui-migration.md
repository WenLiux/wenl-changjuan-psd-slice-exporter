# v0.3 Web UI migration report

## Outcome

The default Windows interface now uses a React/TypeScript frontend rendered in
a pywebview WebView2 host. The existing PSD/PSB parsing, composite reading,
scaling, image encoding, Photoshop fallback, validation, reporting, and output
directory services remain unchanged.

The previous CustomTkinter interface is retained as a rollback path and can be
started with `--legacy-ui` while v0.3 is validated on more Windows machines.

## Architecture

```text
React / TypeScript / CSS
        ↕ structured JSON and task events
app.bridge.AppApi
        ↕
TaskRunner + existing application services
        ↕
PSD / PSB / Photoshop
```

The bridge exposes only explicit file, settings, export, cancellation, output,
and report operations. Python objects and tracebacks are not exposed directly
to React. User-correctable errors use a stable `success/data/error` envelope.

Document parsing and export run on the existing persistent worker. Progress is
pushed to JavaScript; a small event backlog is retained only for startup races.
Preview PNG data is written to an isolated temporary cache and loaded by local
URL rather than repeatedly crossing the bridge as Base64.

## Visual system

- Three restrained glass surfaces: file import, workspace, and task footer.
- CSS variables for color, borders, radii, shadows, and typography.
- Low-amplitude ambient lighting with no continuous decorative animation.
- Native web layout, focus rings, hover/pressed feedback, custom scrollbars,
  segmented controls, switches, selects, toast messages, and progress states.
- Verified without page overflow at 1240 x 820 and 1100 x 720 viewports.
- Explicit solid-background fallback when backdrop blur is unavailable.

## Functional paths connected

- Native PSD/PSB file picker.
- Native WebView2 file-drop full-path handling.
- Background document load and temporary preview cache.
- Stable slice IDs, selection, select-all, and output-dimension estimates.
- Original/custom width, upscale control, PNG/JPEG, JPEG controls, color
  policy, naming, Photoshop fallback, output folder, ZIP, and open-folder
  settings.
- Background export with progress, cancellation, result, report, and folder
  actions.
- Settings persistence through the existing atomic `SettingsStore`.

## Verification

- TypeScript production build succeeds.
- Python regression suite succeeds with the new bridge tests.
- A real `详情切片.psb` completed the bridge path at 750 px: load, preview,
  14-slice export, and validation report.
- Local browser verification confirmed width changes update every displayed
  output dimension.

## Packaging

The PyInstaller specification includes the WebView host dependencies and the
compiled `frontend/dist` directory. `scripts/build_windows.ps1` installs and
builds frontend assets before starting PyInstaller. The installed application
still launches as a normal Windows executable and requires no browser tab or
development server.
