# PSD / PSB 切片工具 UI 视觉重构任务

请先完整检查当前项目的 UI 技术栈、页面结构、组件组织、主题样式和交互逻辑，再开始修改。

---

## 一、任务目标

公开仓库不保留带本机路径的原始参考截图。视觉要求以本规范中的颜色、层级、
交互和验收标准为准；公开版截图说明见 `docs/ui-reference/README.md`。

请将当前界面从普通深色工具风格，重构为目标图中的：

- 深色未来感
- 蓝紫色低饱和光效
- 高级玻璃质感
- 柔和内发光
- 大圆角卡片
- 清晰的层级关系
- 精致但克制的科技感

目标是让它看起来像一款成熟的高端桌面设计工具，而不是网页仪表盘或游戏界面。

---

## 二、重要约束

### 1. 不修改功能逻辑

本次只允许重构视觉层和必要的布局细节，不要修改：

- PSD / PSB 读取逻辑
- 切片计算逻辑
- 导出逻辑
- Photoshop 回退逻辑
- 文件选择逻辑
- 状态管理
- 数据结构
- 组件功能
- 按钮行为
- 表单默认值
- 原有字段和文案含义

不得因为 UI 重构导致：

- 元素错位
- 控件失效
- 文字被遮挡
- 滚动区域失效
- 窗口缩放异常
- 导出任务受影响
- 主线程卡顿
- 阴影或动画影响性能

### 2. 不更换技术栈

继续使用项目当前的 UI 框架。

不要为了视觉效果迁移到新的框架，也不要重写整个项目。

优先通过以下方式实现：

- 统一主题变量
- 公共组件样式
- QSS / CSS / StyleSheet
- 少量自定义绘制
- 轻量阴影与渐变
- 可复用的按钮、卡片、输入框组件

### 3. 不要直接把参考图当背景图

目标图只作为设计参考。

所有界面元素必须是真实可交互控件，不能通过截图、背景图片或覆盖图片模拟。

## 三、整体视觉方向

### 1. 主背景

当前纯灰黑背景改为深蓝黑色背景。

推荐基础色：

```text
窗口背景：
#080D18
#0A101D

一级卡片：
rgba(18, 28, 48, 0.88)

二级卡片：
rgba(23, 34, 56, 0.72)

输入区域：
rgba(10, 18, 33, 0.78)

悬浮状态：
rgba(53, 77, 130, 0.28)
```

背景不要完全纯色，可以加入非常轻微的：

- 左上至右下深蓝渐变
- 局部柔和蓝色光晕
- 极低透明度的亮度变化

不要加入明显纹理、星空、粒子或过度装饰。

### 2. 卡片系统

所有主要区域统一为玻璃卡片：

- 顶部文件选择区
- 左侧文档与切片区
- 右侧导出设置区
- 底部导出状态区

卡片特征：

```text
圆角：18–22 px
内边距：20–24 px
边框：1 px 半透明蓝灰色
背景：深蓝黑半透明
阴影：柔和、扩散范围大、透明度低
内高光：顶部或左上方有轻微亮边
```

推荐边框：

```text
默认：
rgba(112, 145, 210, 0.20)

重点卡片：
rgba(115, 150, 255, 0.34)
```

不要让每个卡片都强烈发光。

普通卡片主要依赖：

- 透明度
- 边框
- 明暗关系
- 微弱阴影

只有选中状态和主按钮使用明显蓝色光效。

## 四、布局调整

整体布局结构保持当前版本：

1. 顶部文件拖入区域
2. 中间左侧文档与切片
3. 中间右侧导出设置
4. 底部状态与操作按钮

但需要优化以下问题。

### 顶部区域

改成更有识别度的文件导入卡片：

- 左侧增加一个发光上传图标容器
- 文件标题字号更大
- 文件路径降低对比度
- 右侧“选择文件”改成高亮主操作按钮
- 补充小字“支持 PSD / PSB 格式”
- 整体垂直居中
- 增加左右留白

顶部区域不要过高，保持紧凑。

### 左侧文档与切片区域

优化信息层级。

#### 文档信息

标题：

```text
文档与切片
```

标题下方显示：

```text
1440 × 31044 px · RGB / 8 位 · 含透明度 · 14 张切片
合成图来源：……
```

要求：

- 标题清晰
- 主信息亮度较高
- 辅助信息降低对比度
- 行距更舒适

#### 预览图

预览图增加：

- 16 px 左右圆角
- 一圈柔和蓝色描边
- 很轻的蓝色外发光
- 轻微底部倒影或阴影

不要让预览图外发光过强。

#### 切片列表

列表区域改成独立的深色容器。

每一行：

- 高度统一
- 14–16 px 圆角
- 行间距 6–8 px
- 默认背景与卡片有轻微明度差
- hover 时轻微提亮
- 选中时显示蓝色描边或淡蓝背景
- 坐标信息使用低对比度灰蓝色
- 尺寸信息右对齐
- Checkbox 统一成蓝色圆角方形

列表表头不要使用粗重实心灰条，改成轻量半透明表头。

“全选”和“全不选”按钮做成尺寸一致的次级按钮。

### 右侧导出设置

右侧设置区保持现有字段，但重新统一组件样式。

#### 分段按钮

以下控件做成统一的 segmented control：

- 原始宽度 / 指定宽度
- PNG / JPEG

样式：

- 外层深色胶囊容器
- 当前选项为蓝紫渐变
- 当前选项有轻微内发光
- 未选项不发光
- 切换动画控制在 120–180 ms
- 不要使用高亮纯蓝大色块

#### 输入框和下拉框

统一：

```text
高度：38–42 px
圆角：9–11 px
背景：深蓝黑
边框：半透明蓝灰
文字：浅灰白
占位文字：低对比度
聚焦状态：边框变亮并出现轻微蓝光
```

不要让所有下拉框默认都是高饱和蓝色背景。

当前界面中大量蓝色实心下拉框需要改为深色输入框，仅在：

- hover
- focus
- active

时显示蓝色强调。

#### 开关

开关使用：

- 关闭：暗灰蓝
- 开启：蓝紫渐变
- 圆点带轻微高光
- 不使用过强外发光

#### 警告文字

“使用前请保存并关闭 Photoshop 中所有打开的文档。”

保留橙黄色提示，但降低饱和度：

```text
#D7A84D
```

## 五、按钮规范

请建立统一按钮体系，不要单独给每个按钮写完全不同的样式。

### Primary Button

用于：

- 选择文件
- 开始导出

样式：

- 蓝紫色渐变
- 柔和内高光
- 半透明亮边
- 轻微外发光
- 白色文字
- hover 时亮度提升
- pressed 时缩小到 0.98 或降低高光
- 动画 120–160 ms

推荐渐变：

```text
#365CEB → #5B6EFF
```

主按钮不要做成刺眼的霓虹灯。

### Secondary Button

用于：

- 打开输出
- 查看报告
- 浏览
- 全选
- 全不选

样式：

- 深色半透明背景
- 半透明边框
- hover 时背景变亮
- 可使用轻微蓝色描边
- 不要默认强发光

### Danger Button

用于：

- 取消

样式：

- 深红紫半透明背景
- 低饱和红色边框
- hover 时稍微变亮
- 不要使用纯红大色块

推荐色：

```text
背景：rgba(122, 46, 75, 0.42)
边框：rgba(225, 92, 127, 0.42)
文字：#F0A6B8
```

## 七、光效原则

参考图的质感来自层级、渐变和微弱光效，而不是给所有元素添加蓝色阴影。

请严格控制。

### 可以发光

- 主按钮
- 当前选中的分段按钮
- 开启状态的开关
- 预览图边缘
- 进度条末端
- 当前聚焦输入框

### 不应该发光

- 普通文本
- 每一个输入框
- 每一个列表项
- 所有卡片边缘
- 所有图标
- 所有下拉框

光效要柔和、扩散、低透明度。

## 八、底部状态区域

底部状态栏重构成独立横向卡片。

左侧：

- “导出完成：14 张切片”
- 输出路径和耗时
- 进度条

右侧：

- 打开输出
- 查看报告
- 取消
- 开始导出

进度条：

- 深色轨道
- 蓝紫色渐变填充
- 末端有小范围亮点
- 不使用整条强光
- 完成状态下保持清晰但不过曝

主按钮“开始导出”需要成为底部最强视觉焦点。

建议图标：

- 上传
- 文件夹
- 报告
- 关闭
- 开始导出
- 下拉箭头
- 浏览目录

要求：

- 线条粗细统一
- 不混用 Emoji

- 图标颜色跟随按钮文字

## 十一、代码实现要求

1. 先分析当前 UI 文件和组件结构。
2. 将颜色、圆角、间距、边框、阴影整理成统一主题变量。

## 十二、执行顺序

不要一次性无结构地修改全部文件，请按照以下顺序执行。

输出：

- 当前 UI 技术栈
- 主窗口入口
- 样式文件位置
- 主要组件列表

### 第二阶段：建立主题系统

### 第三阶段：重构主界面

1. 顶部文件选择区

## 十三、验收标准

完成后界面应满足：

- 第一眼明显比旧版更加现代和高级
- 与目标图具有相似的深色玻璃氛围
- 仍然是一款专业生产力工具
- 不像游戏启动器
- 不像加密货币网页
- 不像单纯套了一层蓝色发光滤镜
- 信息密度与当前版本基本一致
- 功能入口没有减少
- 控件状态容易识别
- 长时间使用不会刺眼
- 蓝色强调色不超过界面视觉面积的约 15%
- 普通区域主要依赖深浅层次，而不是蓝色填充
- 所有原功能保持可用

完成后请提供：

1. 修改文件清单
2. 主要设计变量说明
3. 修改前后对比说明
4. 启动和测试结果
5. 仍可能存在的问题

## 十五、重点防止的问题

这次重构不是简单地给所有控件加蓝色发光。

必须重点控制：

1. 大面积保持深蓝黑，仅少数交互状态发光。
2. 输入框默认保持暗色，不要整排铺满高饱和蓝色。
3. 卡片通过透明度、边框和明暗关系形成层级，而不是依赖厚重灰色底块。
4. 禁止给所有元素统一添加强烈的蓝色 `box-shadow`。
5. 禁止做成廉价电竞风、网页仪表盘或加密货币交易界面。
